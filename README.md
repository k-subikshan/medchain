# mediblock

## Fast Demo Setup

1. Create MySQL database `medi`.
2. Update `src/main/resources/application.properties` with your MySQL username/password.
3. Run with Java 17 and Maven: `./mvnw spring-boot:run`.
4. Open `http://localhost:8080/login`.

### Demo accounts
- admin / admin123
- doctor / doctor123
- manufacturer / manufacturer123
- pharmacy / pharmacy123
- patient / patient123

### Demo flow
Manufacturer -> Medicine Registration -> Batch Management -> Doctor -> Create Prescription -> Pharmacy -> Verify Medicine / Verify Prescription -> Admin -> Blockchain Ledger.

The project uses a local SHA-256 hash chain persisted in MySQL. Each medicine, batch, and prescription creates a ledger block containing a data hash, previous block hash, and block hash. The Admin Blockchain page verifies the chain integrity.


## Patient OTP dispensing
- A doctor can enable **Require patient OTP before dispensing** when creating a prescription.
- Pharmacy requests a dose; MedChain emails a 6-digit OTP to the patient's registered email.
- The patient gives the OTP to the pharmacist; the pharmacist enters it to complete that dose.
- OTPs expire after 5 minutes and are single-use. OTP values are never written to the blockchain.
- Configure SMTP with `MAIL_USERNAME`, `MAIL_PASSWORD`, and optionally `MAIL_HOST`/`MAIL_PORT`. For Gmail, use an App Password.
- Set `MEDIBLOCK_DEMO_PATIENT_EMAIL` for the seeded `P-1021` demo patient if their DB email is empty.


## Latest patient identity and email verification flow

1. Patient logs in and opens **Profile & Email**.
2. Patient enters their own email and clicks **Save Email & Send OTP**.
3. The OTP is sent by email and must be entered on the same page.
4. Only after `EMAIL_VERIFIED` can a doctor create a prescription for that patient.
5. During prescription creation, the doctor must enter the patient's registered email. If it is not verified yet, the first submission sends an email OTP and the second submission with the OTP creates the prescription.
6. Patient prescription/history pages are filtered by the logged-in patient's `patientId`; one patient cannot see another patient's prescriptions.
7. Dispensing OTP remains a separate optional control selected by the doctor and is generated by the pharmacy at dispense time.

### Environment variables for Gmail
```bash
export MAIL_USERNAME="yourgmail@gmail.com"
export MAIL_PASSWORD="your-16-character-gmail-app-password"
export MEDIBLOCK_DEMO_PATIENT_EMAIL="patient-email@gmail.com"
```
Use a Gmail App Password, not the normal Gmail password.
